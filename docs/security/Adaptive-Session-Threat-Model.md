## Purpose, assets and trust boundaries

This threat model covers the minimal client, gateway, session orchestrator, fast
and deliberative lanes, retrieval/tools, context store, verifier, caches,
telemetry and compute placement. Assets are drafts, identity, consent, prompts,
session packages, evidence, tool authority, cache state, models and receipts.

```text
device | institution gateway | AI control plane | model/compute plane
       | evidence/tool plane  | storage/cache   | federation gateway
```

Every line is a trust boundary; federation adds a separate institution authority.

## Scope and out of scope

The scope is the adaptive session and its direct dependencies. General campus
endpoint compromise, physical datacenter security and model-training supply chain
are out of scope except where they cross a named boundary.

## Architecture and ownership boundaries

Clients own local drafts; the gateway owns ingress; the orchestrator owns session
generation; AI services own routing/context/verification; compute owns placement;
storage owns persistence; security owns incident coordination.

## Dependencies and adapters

Identity, policy, storage, compute, retrieval, tools and telemetry are dependencies
through signed/versioned interfaces. Model and cache products are untrusted
adapters until their output and scope are verified.

## Threats and controls

| Threat | Example | Required controls |
|---|---|---|
| draft surveillance | background keylogging or timing profile | local default, no timing telemetry, consent, network tests |
| cross-tenant cache leak | timing reveals another user's prefix | scoped salts, strong hashes, authorization before lookup |
| package forgery/rollback | stale plan replaces current state | integrity, generation checks, expiry, revocation tombstone |
| prompt/retrieval injection | document directs tool misuse | untrusted-content labels, tool isolation, verifier |
| route manipulation | user forces unapproved model/provider | server policy, signed route decision, separate placement |
| capacity denial | agents exhaust strong-model queue | budgets, admission control, cancellation, bounded fan-out |
| telemetry leakage | prompts in traces | structured allowlist, redaction tests, access audit |
| false transparency | UI exposes fabricated route rationale | route evidence generated by control plane, not model prose |
| federation exfiltration | protected session placed remotely | classification/locality filter, explicit federation policy |

## Security requirements

- `SEC-ADAPT-001`: clients MUST authenticate only to the institution gateway and MUST NOT receive backend credentials.
- `SEC-ADAPT-002`: packages and route decisions MUST be integrity protected and bound to institution, subject, session, generation and policy version.
- `SEC-ADAPT-003`: tools MUST receive separately authorized operation grants; model selection is not tool authorization.
- `SEC-ADAPT-004`: high-risk output MUST fail closed when verification is unavailable.
- `SEC-ADAPT-005`: diagnostic capture MUST be time-bound, approved, visibly active, access-controlled and deleted by policy.

## Deployment, capacity and routing

Separate fast and deliberative pools limit blast radius. Network policy prevents
direct client/runtime paths. Rate limits, queue ceilings, bounded agent fan-out
and per-purpose budgets resist resource exhaustion.

## Failure, recovery and fallback

Authorization or verifier failure fails closed for protected/high-risk output.
Cache loss recomputes. Strong-model loss uses the disclosed degradation ladder.
Package-store recovery replays revocation tombstones before accepting traffic.

## Testing and acceptance

Tests cover replay, rollback, cross-user/institution cache probes, malicious
retrieval, prompt injection, tool escalation, route tampering, federation denial,
overload, cancellation races, telemetry secrets and restored-backup revocation.
`SEC-ADAPT-ACC-001` passes only when every threat has a positive protection test
and at least one adversarial failure fixture.
